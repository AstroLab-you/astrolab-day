# Калькулятор натальной карты и приложение «прогноз на день»

Численный расчёт карты рождения на Swiss Ephemeris: положения планет и точек,
оси, куспиды домов, аспекты. Поверх него — транзиты на каждый день
и приложение для Android, которое считает всё прямо в телефоне.

Исходный код открыт под AGPL-3.0 (см. `LICENSE`) — этого требует лицензия
Swiss Ephemeris, на которой стоит расчёт.

```bash
cd tools/natal-calc
npm install && ./fetch-ephe.sh      # один раз: обёртка библиотеки и файлы эфемерид

node src/cli.ts --date 1990-05-14 --time 14:30 \
  --lat 55.7558 --lon 37.6173 --tz Europe/Moscow          # таблица
node src/cli.ts ... --json                                # то же в JSON

npm test            # перевод местного времени в UTC, WASM = нативный расчёт
npm run validate    # сверка с astro.com и JPL Horizons (нужна сеть, ~2 мин)
```

Node — из nvm: `export PATH="$HOME/.nvm/versions/node/v22.23.2/bin:$PATH"`.

## Экраны приложения

Прототипы приложения «на каждый день»: открыть и за пять секунд оценить
день, как прогноз погоды. Оба файла самодостаточные, открываются двойным
кликом.

Экран дня пересчитывается командой — семь дней, сегодня и шесть
предыдущих (вперёд не показываем):

```bash
node src/day.ts --date 1990-05-14 --time 14:30 --lat 55.7558 --lon 37.6173 \
  --tz Europe/Moscow --place Москва --write day.html
```

Транзиты считаются по-настоящему, по правилам документа «Методика
натального профиля» (разделы о транзитах); пока астролог их не
утвердил, это прототип. Сила считается по часам местного дня и сводится
в восемь 3-часовых отрезков (0–3 … 21–24); сила отрезка — процентиль среди
всех отрезков 365 своих дней. Расчёт занимает около 0,6 с: натальная
карта ~19 мс, 365 дней по часам ~580 мс (Луна — по эфемериде каждый час,
остальные планеты — от полудня по скорости). Время шагов скрипт печатает
в stderr.

**`day.html` — экран дня.** По каждой сфере жизни — полоса текущих трёх
часов (у прошлых дней — тех же часов), она перестраивается сама каждые
3 часа: цвет — тон (зелёный помогает, красный мешает, стрелка дублирует
цвет для дальтоников), длина — сила относительно других часов этого же
человека. Сверху — колесо
с небом выбранного дня: планеты дня в ваших домах, натальные точки —
метками, в центре фраза дня. По тапу на полосу она раскрывается на месте:
тон, сила и таблица по 3 часа, как у Windy — «Итого» с числами и строка
на каждое влияние: значки аспекта, смысл («Лёгкое настроение в работе»)
и клетки, цвет которых — помогает или мешает, насыщенность — насколько.
Кто к кому, показывает подсветка пары на колесе при наведении. Данные
кладёт `src/day.ts` в блок `#day-data`.

**`wheel.html` — натальная карта.** В приложении — только круг на экране
дня (`?embed=1`), отдельной страницы карты там нет. Открытый напрямую —
интерактивный круг; при открытии он
собирается слой за слоем в изометрии и разворачивается во фронтальный вид
(тап — пропустить, «▶ Собрать заново» — повторить). Открывается двойным кликом, внешних
ресурсов нет. Тап по планете, аспекту, знаку или дому подсвечивает связанное
и показывает карточку; есть фильтр аспектов и переключатель «Асцендент
слева / Овен слева». Зодиак идёт против часовой стрелки, как принято
в астрологических программах.

Данные — JSON расчёта внутри страницы. Пересчитать под другого человека:

```bash
node src/cli.ts --date 1990-05-14 --time 14:30 --lat 55.7558 --lon 37.6173 \
  --tz Europe/Moscow --json | node src/embed.ts wheel.html "Натальная карта" "Москва"
```

## Приложение для Android

`app/` — Capacitor-обёртка вокруг `day.html` и `wheel.html`. В приложении
страница не получает готовых данных: человек вводит дату, время и место
рождения, они хранятся только в телефоне (`localStorage`), а расчёт идёт
там же — тот же `src/forecast.ts`, что и в Node, в фоновом потоке
(`src/app-engine.ts` → `www/engine.js`).

- **Swiss Ephemeris в WebAssembly** — `wasm/sweph.mjs`, собирается
  `wasm/build.sh` (нужен Emscripten) из тех же C-исходников 2.10.03, что
  в пакете `sweph`; файлы эфемерид 1800–2400 гг. вшиты. `src/wasm.test.ts`
  проверяет, что карты и прогноз совпадают с нативным расчётом до 1e-9°.
  По времени разницы почти нет: ~0,4 с в Node, ~0,45 с в Chromium.
- **Места рождения** — `app/cities.json`, выжимка GeoNames (CC BY 4.0)
  командой `src/build-cities.ts`: 43 тыс. мест с русскими названиями,
  координатами и часовым поясом. Россия и соседи — от 1000 жителей,
  остальной мир — от 15 000. Работает без интернета.
- **Луна** — тап по плашке «Луна в … · N дом» под датой открывает лунный
  календарь (`src/moon-calendar.ts`, сообщение движку `{type:'moon'}`):
  фаза сейчас с рисунком и долей освещённого диска, знак и дом карты;
  Луна без курса — от последнего точного аспекта Луны (0°, 60°, 90°, 120°,
  180° к планетам от Солнца до Плутона) до перехода в следующий знак;
  ближайшие фазы с точным временем и затмениями; месяц сеткой — фаза
  и знак на каждый день, тап по дню — переход в другой знак и фаза
  с временем. Затмения — по геометрии в момент новолуния и полнолуния;
  `src/moon-calendar.test.ts` сверяет их с каталогом NASA за 2026–2027
  и фазы — до 2 минут. Лунных суток и «календаря стрижек» нет намеренно.
- **Меню** (кнопка в верхней строке) — всё, что не про сегодняшний день:
  данные рождения, «Небо над вами», шаги за сегодня, обновление,
  статистика. На самом экране остаются дата, колесо и полосы.
- **Обновления** — пункт меню «Проверить обновление» сверяет версию с
  последним релизом этого репозитория на GitHub и даёт ссылку на APK.
  Android ставит его поверх, данные сохраняются — если APK подписан тем же
  ключом.
- **Шаги** — задел под игру «полёт к планетам» (шаги за день → путь до
  планет, правила впереди). Считает телефон: датчик `TYPE_STEP_COUNTER`
  копит шаги в чипе датчиков и без приложения. Плагин `Steps`
  (`app/android/.../StepsPlugin.java`, `StepStore.java`, `StepsReceiver.java`)
  читает его по будильнику в начале каждого часа и при открытии меню и
  раскладывает шаги между чтениями по часам пропорционально времени. Если
  чтение пропустило больше часа (телефон придержал будильник), часы
  промежутка помечаются как оценка — в меню они заштрихованы и со знаком ≈.
  Перезагрузку узнаёт по времени загрузки системы. Тап по пункту меню
  раскрывает шаги по часам за сегодня и вчера. С Android 10 нужно
  разрешение «Физическая активность». Считаются только шаги телефона, не
  браслета; данные о шагах остаются в телефоне и в статистику не уходят.
  В первый день счёт идёт с момента установки.

- **Небо над вами** — `sky.html`: карта звёздного неба в реальном времени.
  Открывается тапом по центру круга на экране дня или из меню. Планету
  держат в кольце прицела 3 секунды — кольцо заполняется и открывается
  карточка: рисунок, факт, расстояние сейчас (и сколько идёт свет), фаза
  Луны, ретроградность, знак и созвездие, дом в вашей карте. Градусов
  на экране нет — стороны света словами, место — ближайшим городом.
  Куда смотрит телефон — датчик ориентации (`deviceorientationabsolute`),
  где человек — GPS; звёзды и созвездия — `app/sky.json` (d3-celestial,
  BSD-3, собирает `src/build-sky.ts`), планеты — тот же движок
  (`src/sky-now.ts`, сообщение `{type:'sky'}`). На эклиптике — знаки
  зодиака, под ними — созвездия: карточка планеты показывает оба и
  объясняет расхождение (прецессия). Положения сверены с `swe_azalt`:
  расхождение ≤ 0,5° — это J2000 против даты, на порядок меньше ошибки
  компаса телефона. Без датчиков небо водят пальцем, в браузере —
  `sky.html?az=…&alt=…`. Лицензии данных — `app/THIRD_PARTY.md`.
- **Статистика и объявления** — через наш бэкенд (`backend/src/modules/app`,
  сервер в Москве). Приложение сдаёт обезличенные события пачкой: открытия,
  сферы, листание дней, проверку обновлений; телефон известен только
  случайным номером, данных рождения в событиях нет. Выключается
  в меню. Объявления астролог публикует в панели (раздел
  «Приложение»), приложение показывает их карточкой над экраном дня.
  Для проверки страницы против другого сервера: `localStorage.astrolab_api`.

Сборка (нужны JDK 17+ и Android SDK; ключ подписи — в
`~/.config/astrolab-day/keystore.properties`, вне репозитория):

```bash
cd app && npm install
export JAVA_HOME=… ANDROID_HOME=…
./build.sh          # → app/dist/astrolab-day-<версия>.apk
./build.sh www      # только страницы в app/www — посмотреть в браузере
./release.sh        # сборка + релиз в github.com/AstroLab-you/astrolab-day
```

Версия — в `app/package.json`; перед релизом её надо поднять.

## Методика

[Swiss Ephemeris](https://www.astro.com/swisseph/swephinfo_e.htm) (Astrodienst,
Д. Кох и А. Трейндл) — стандарт астрологических программ. Это не своя теория
движения планет, а сжатая до 2 МБ эфемерида NASA JPL **DE441** плюс полный
набор астрономических редукций. Точность относительно DE441 — тысячные доли
угловой секунды. Здесь библиотека подключена через Node-обёртку
[`sweph`](https://github.com/timotejroiko/sweph) — тот же C-код, версия 2.10.03.

Конвейер (`src/natal.ts`):

| Шаг | Что происходит | Где ошибаются |
|---|---|---|
| 1. Местное → UTC | смещение пояса из tzdb с историей переходов (`src/time.ts`) | летнее время СССР, «вечное лето» 2011–2014, переезды регионов между поясами |
| 2. UTC → юлианская дата | `swe_utc_to_jd`: високосные секунды, ΔT = TT − UT1 | — |
| 3. Планеты | `swe_calc_ut`: видимые геоцентрические долготы на истинное равноденствие даты (световое время, аберрация, отклонение света, нутация) | без файлов `.se1` библиотека молча считает по Мошье — ловится по флагу |
| 4. Оси и дома | `swe_houses_ex2`: звёздное время → ARMC → Асцендент, MC, куспиды | Плацидус и Кох не определены за полярным кругом — Мурманск, Норильск, Воркута |
| 5. Знаки, дома планет, аспекты | здесь, в коде | орбисы — вопрос школы, не астрономии |

Градусы обрезаются до секунды, а не округляются: 29°59′59.7″ Овна не должно
стать 0° Тельца.

## Входные параметры

**Обязательные** — то, что даёт клиент:

| Параметр | Зачем | Цена ошибки |
|---|---|---|
| Дата рождения | всё | — |
| Время рождения, местное | оси, дома, Луна | 4 минуты ≈ 1° Асцендента; час ≈ знак |
| Место → широта и долгота | оси и дома | 1° долготы = 4 минуты времени |
| Часовой пояс (IANA, например `Europe/Moscow`) | перевод в UTC | час — Асцендент уезжает на знак |

**Если время неизвестно** — `timeKnown: false` / `--no-time`: карта на 12:00
местного, без домов и осей, Луна с точностью ±6.5°.

**Явное смещение** `utcOffset` / `--offset` перекрывает пояс — когда астролог
знает его точнее (из свидетельства, по атласу) или для местного среднего
времени до введения поясов: tzdb даёт LMT столицы пояса, а не города.

**Настройки** (у каждой есть значение по умолчанию):

| Настройка | По умолчанию | Варианты |
|---|---|---|
| Система домов | Плацидус `P` | Кох `K`, Порфирий `O`, Региомонтан `R`, Кампанус `C`, равнодомная `E`, целые знаки `W`, Алькабитий `B`, Морин `M`, топоцентрическая `T` |
| Зодиак | тропический | сидерический (`--sidereal`, аянамша Лахири) |
| Лунный узел | истинный | средний (`--mean-node`) |
| Орбисы | соед./опп. 8°, трин/квадрат 7°, секстиль 5°; Солнцу и Луне +2°; узлу, Лилит, Хирону 3°; осям 5° | `settings.orbs` |

## Что на выходе

`calculateNatal(input)` → `NatalChart` (пример: `--json`):

- `time` — местное время, смещение и его источник, UTC, JD UT1 и TT, ΔT;
- `bodies` — Солнце…Плутон, северный и южный узлы, Лилит (средняя), Хирон:
  долгота 0–360°, знак, градус в знаке, широта, расстояние, скорость,
  ретроградность, дом;
- `angles` — Асцендент, MC, Десцендент, IC, Вертекс;
- `houses` — 12 куспидов;
- `aspects` — мажорные аспекты с орбисом и признаком сходящийся/расходящийся;
- `meta.warnings` — всё, что надо показать астрологу: несуществующее или
  неоднозначное время из-за перевода часов, полярный круг, падение на Мошье.

## Сверка

`src/validate.ts` прогоняет восемь контрольных карт (`src/cases.ts`) через два
бесплатных сервиса. Сверяется один и тот же момент времени, чтобы ошибку
пояса не смешать с ошибкой эфемериды.

| Сервис | Что проверяет | Результат 2026-10-01 |
|---|---|---|
| [astro.com swetest](https://www.astro.com/swisseph/swetest.htm) — веб-версия эталонной утилиты авторов библиотеки | что мы правильно ею пользуемся: дата, флаги, дома, узлы, Лилит, Хирон | тела и куспиды ≤ **0.0002″** |
| то же, по несжатой JPL DE441 | цена сжатия файлов `.se1` | ≤ **0.001″** |
| [JPL Horizons](https://ssd.jpl.nasa.gov/horizons/) (NASA) — независимый расчёт | планеты | ≤ **0.1″** для 1968–2024, ≤ **0.8″** для 1879 |
| то же, Луна | | ≤ **0.3″** |
| то же, Асцендент и MC — пересчёт из звёздного времени Horizons | | ≤ **1.3″** |

Итог: **296 сравнений, все в допуске.** Карта Эйнштейна (Ульм, 14.03.1879,
11:30 LMT, рейтинг AA в Astro-Databank) даёт Асцендент 11°38′ Рака и MC
12°50′ Рыб — до минуты как в публичных разборах
([astrotheme](https://www.astrotheme.com/astrology/Albert_Einstein),
[astro-charts](https://astro-charts.com/persons/chart/albert-einstein/)).

Для масштаба: время рождения известно с точностью до минуты, а минута —
это 15′ на осях, то есть 900″. Расчётная погрешность меньше этой
неопределённости в сотни раз.

Чем объясняются остатки:

- **+0.05″ у всех планет разом** — разные модели прецессии и нутации:
  IAU 2006 у Swiss Ephemeris против IAU 1976/80 у Horizons;
- **оси у карты 2024 года, ~1″** — ΔT на недавние даты в Swiss Ephemeris
  экстраполирован (69.05 с против фактических 69.19 по IERS);
- **ловушка, в которую валидатор однажды попал:** Horizons понимает «UT»
  после 1962 года как UTC, а не как UT1. Если передать ему UT1, появляется
  мнимое расхождение до 13″ на осях — DUT1. Сейчас Horizons получает UTC.

## Ограничения

- **Геокодер — только в приложении** (`app/cities.json`, GeoNames). В CLI
  широту, долготу и пояс задают руками.
- **tzdb для СССР до 1991 года местами приблизительна**: регионы переходили
  между поясами, и не каждый переход есть в базе. Для спорных случаев есть
  `utcOffset`. Профессиональные программы используют атлас ACS — он платный.
- **До 1800 и после 2400 года** нужны другие файлы эфемерид, а Хирон
  считается только для 675–4650 годов.
